## 一、环境要求

| 软件 | 版本要求 |
|------|----------|
| JDK | 17+ |
| Maven | 3.6+ |
| Node.js | 16+ |
| MySQL | 8.0+ |
| MQTTX | 最新版（设备模拟） |
| HBuilderX | 最新版（小程序） |

---

## 二、部署步骤

### 2.1 数据库初始化

1. 启动 MySQL 服务
2. 创建数据库并导入数据：

```bash
mysql -u root -p < sql/lekang_elderly.sql
```

3. 数据库配置文件：[elderly-care-backend/src/main/resources/application.yml](file:///d:/新建文件夹/project/elderly-care-backend/src/main/resources/application.yml)

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/lekang_elderly?...
    username: root
    password: root
```

> 默认账号 `root/root`，如不一致请修改 `application.yml`。

### 2.2 启动后端服务

```bash
cd elderly-care-backend
mvn spring-boot:run
```

- 启动成功日志: `Started ElderlyCareApplication`
- MQTT 订阅成功日志: `MQTT 订阅成功: topic=device/fall/#`
- 服务地址: `http://localhost:8080/api`

### 2.3 启动 Web 前端

```bash
cd elderly-care-web
npm install
npm run dev
```

- 启动成功后访问: `http://localhost:5173`
- Vite 代理 `/api` → `http://localhost:8080`

### 2.4 运行小程序

1. 打开 HBuilderX
2. 文件 → 打开目录 → 选择 `elderly-care-mp`
3. 运行 → 运行到浏览器 → Chrome（H5 模式）
4. 或运行 → 运行到小程序模拟器 → 微信开发者工具

### 2.5 启动 MQTTX 设备模拟

1. 打开 MQTTX
2. 新建连接：
   - Host: `broker.emqx.io`
   - Port: `1883`
   - 点 Connect
3. 发布消息：
   - Topic: `device/fall/event`
   - Payload:
   ```json
   {"deviceId":"FALL-001","type":"FALL","timestamp":1788964481207,"location":"房间内","severity":"HIGH"}
   ```

## 三、验收流程

### 验收点 1：登录注册

1. 打开 `http://localhost:5173`
2. 输入账号 `admin`，密码 `123456`
3. 登录成功，进入工作台
4. 退出后可注册新账号

### 验收点 2：入住登记管理（CRUD）

1. 登录后点击左侧「入住管理」
2. 查看老人列表（3 条测试数据）
3. 点击「新增」填写老人信息并保存
4. 点击「编辑」修改信息
5. 点击「删除」删除记录
6. 列表实时更新

### 验收点 3：MQTT 跌倒告警（核心）

1. MQTTX 连接 `broker.emqx.io:1883`
2. 后端控制台显示 `MQTT 订阅成功: topic=device/fall/#`
3. MQTTX 发布消息到 `device/fall/event`
4. 后端控制台打印 `收到MQTT消息` 和 `告警已入库`
5. Web 后台「告警管理」刷新，出现新告警（状态：待处理）
6. 点击「处理」填写处理备注，状态变为「已处理」

### 验收点 4：小程序

1. HBuilderX 运行小程序到浏览器
2. 登录账号 `family01` / `123456`（家属账号）
3. 查看老人信息和告警列表

## 六、常见问题

### Q1: 后端启动报数据库连接错误
A: 检查 MySQL 是否启动，`application.yml` 中密码是否正确。

### Q2: MQTT 订阅失败
A: 确认能访问 `broker.emqx.io:1883`（公共 Broker，无需本地部署）。

### Q3: 前端登录后 403
A: 后端 Token 过期，清除浏览器 localStorage 的 token 后重新登录。

### Q4: MQTTX 发消息后后台没收到
A: 检查 MQTTX 的 Topic 是否为 `device/fall/event`，deviceId 是否为 `FALL-001`。
